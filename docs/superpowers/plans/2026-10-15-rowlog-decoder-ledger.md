# Journal des décisions : décodeur RowLog Contents

Décisions prises seul pendant l'exécution autonome demandée le 15 octobre 2026, avec la raison et ce qu'elles coûtent si elles sont fausses. Ce journal sert à auditer le travail sans relire les transcripts.

## Avant le code

1. « external harm review » est lu comme la relecture externe du code (skill `external-code-review`) : aucun autre skill ne porte ce nom. Si c'était autre chose, la dernière étape est à refaire.
2. Trois panels de cinq relecteurs sur la spec (v1, v2, v3), puis une v4 corrigée sans quatrième panel : le panel du plan relit la spec comme référence et sert de quatrième passage. Coût si faux : un défaut de la v4 découvert pendant l'implémentation. Chaque panel a surtout trouvé des défauts dans les correctifs du précédent, ce qui justifiait les deux premières reprises.
3. L'ancre « ligne actuelle » (approche 3) est gardée, comme Rudi l'a validé, mais restreinte aux tables clustered sans ADR : en heap la recherche par `%%physloc%%` balaie la table, et sous ADR `DBCC PAGE` montre des octets annulés. Coût : pas de reconstruction arrière depuis la ligne actuelle dans ces deux cas.
4. In-Memory OLTP hors périmètre, mesuré à la demande de Rudi : `LOP_HK` opaque dans `fn_dblog`, lignes lisibles par `sys.fn_dblog_xtp` dans un format propre. Candidat pour une spec C.
5. Le plan n'a pas été « généré puis rejoué » à partir d'une implémentation jetable : il donne le code complet des composants purs, et les deux dispositions non documentées sont confiées à une tâche de recherche (tâche 4) avant le code qui en dépend. Le panel du plan compile et exécute ce code. Coût : des défauts de code du plan trouvés par les implémenteurs plutôt qu'avant.
6. Panel de cinq sur le plan (tag `78953a57d6ec`) : toutes les trouvailles retenues, sauf celles qui demandaient d'écrire le code de la tâche 4 avant la recherche. Le code des tâches 2, 5 et 6 corrigé a été recompilé et exécuté hors arbre (41 tests). Coût si faux : un défaut du plan trouvé par un implémenteur, ce que les briefs l'autorisent à signaler.
7. Spec v5 : un retour arrière partiel ADR (`LOP_CTR_NEST_ABORT` sans enregistrement de compensation) empoisonne toute la chaîne de la ligne, puis la règle a été restreinte aux seuls retours ADR, les compensations classiques arrêtant la chaîne à leur enregistrement. Coût si faux : des reconstructions refusées à tort, jamais une valeur fausse affichée.
8. Ancre 3 réécrite dans l'ordre de la spec §7.2 : la ligne est tenue (`HOLDLOCK`) avant la lecture du suffixe du journal, et le suffixe est ajouté au cache dans un rappel pendant que la ligne est tenue. Coût : une transaction SERIALIZABLE de quelques centaines de millisecondes sur la base analysée, au clic explicite seulement.
9. Tâche 4 : la disposition de `LOP_MODIFY_COLUMNS` n'est déterminée que par la colonne `Log Record` (règle A, 48 cas sur les quatre versions) ; les colonnes `RowLog Contents` seules échouent sur les lignes ADR sans RCSI et ne donnent pas le dernier fragment sans la ligne précédente. Décision : importer `Log Record` pour ces enregistrements seulement (nouvelle tâche 8a), spec passée en v6 (§2, §3, §6.2), règle B abandonnée. Coût si faux : une colonne de plus dans le cache, et un cache importé avant ce changement montre ces enregistrements comme « layout unknown ».
10. Relecture de la tâche 9 sur des chaînes réelles (2019, 2022) : trois cas donnaient une ligne plausible et fausse. Spec passée en v7 (§7.3, §7.4) : une transaction annulée dont on sélectionne un enregistrement et qui avait d'abord annulé un savepoint n'est pas rejouée ; un retour ADR est toute transaction (validée ou annulée en entier) qui annule sans compensation de ligne, et il empoisonne la chaîne ; une suppression sépare deux vies d'une clé (la réinsertion sous ADR est un `LOP_MODIFY_ROW` sur le fantôme). Seules les compensations des quatre opérations de ligne comptent comme compensations. Coût si faux : des reconstructions refusées à tort, jamais une ligne fausse.

## Pendant l'exécution

11. Les implémenteurs des tâches 7 et 8 ont travaillé à partir de prose et de la note de recherche, pas de code donné par le plan : les dispositions ne sont pas documentées et un code écrit d'avance aurait été une supposition. Coût si faux : une boucle de correction sur ces tâches.
12. `DefaultValue` est formaté en SQL (`CONVERT` avec style selon le type de base) plutôt qu'en C#, parce que la capture des fixtures réutilise la même requête. Coût si faux : une valeur par défaut affichée sous une forme textuelle inattendue mais exacte.
13. `TypeDecoder` vérifie la longueur exacte de chaque type de taille fixe et signale toute entrée invalide par une `ArgumentException` lisible. Coût : aucun au-delà de messages d'erreur plus stricts.
14. Les colonnes sparse ne sont jamais lues (« sparse column not decoded ») ; une table compressée est détectée par le schéma et sa ligne entière marquée « compressed rows are not decoded ». La compression est hors périmètre, ne rien montrer vaut mieux que montrer faux. Coût si faux : une détection qui se déclenche à tort masquerait une ligne lisible.
15. Les index clustered non uniques partitionnés ne sont pas pris en charge (clé non décodable) : il faudrait `partition_ordinal` dans le schéma et une recapture de toutes les fixtures. Coût : pas de reconstruction par clé sur ces tables, avec un message explicite.
16. Le lecteur de la ligne actuelle ouvre ses connexions avec `Pooling=false` (le niveau SERIALIZABLE fuyait dans le pool), et une clé varchar qui ne fait pas l'aller-retour par la page de code de la base rend l'ancre 3 indisponible avec un message. Coût si faux : ancre 3 refusée pour certaines clés non latines.
17. Le contrôleur a relu lui-même les petites rondes de correction (moins de 10 Ko de diff hors données), en vérifiant les affirmations sur les données ; les tâches importantes ont eu un relecteur neuf. Coût si faux : un défaut dans un correctif qu'un relecteur neuf aurait vu, la relecture finale servant de filet.

## Relectures finales

18. Trois relectures du code complet : un sous-agent Claude (relecture finale), codex (conformité à la spec), agy (casse : 31 mutations, 6 détectées). Leurs trouvailles ont été corrigées en une vague en deux envois, le comportement d'abord (F1 à F9), puis les tests manquants contre le code corrigé : les 25 mutations non détectées le sont toutes désormais.
19. Une relecture ciblée de la vague a trouvé une régression introduite par elle : une suppression annulée par un retour à un savepoint coupait la vie d'une clé, et un rejeu passait alors un retour ADR sans avertir. Avec un second défaut (inspections concurrentes sur un cache non partagé), elle a été corrigée par un envoi ciblé, malgré la règle d'une seule vague, parce qu'elle contredit la garantie « refusé, jamais une ligne fausse ». Coût : un envoi de plus.
20. Restent parqués, sans correction : le roulement de `smalldatetime` sur un motif d'octets invalide ; l'ancre 3 qui accepte une ligne actuelle aux colonnes hors ligne ou non décodées (elles s'affichent inconnues) ; la source de schéma hors ligne gardée après réimport d'une autre base ; un ADD COLUMN sans réécriture qui donne « current row is not this row » ; un déplacement de pointeur hors ligne montré comme un changement de valeur. Coût si faux : des messages trompeurs ou des refus, jamais une valeur fausse affichée en silence.
